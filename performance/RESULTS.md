# StockFlow 성능 테스트 결과

## 1. 테스트 개요

StockFlow의 상품 조회 성능, Redis 캐시 사용 여부에 따른 응답 시간, 동시 주문 처리 시 재고 정합성을 검증했습니다.

**테스트 환경**
- Spring Boot 4.1.2 / Java 21
- PostgreSQL 17 / Redis 7 / RabbitMQ 4.3
- Docker Compose 기반 로컬 실행
- Grafana k6 부하 테스트
- 측정일: 2026-11-13

## 2. 상품 목록 조회 부하 테스트

대상 API: `GET /api/products?page=0&size=10`

각 가상 사용자는 요청 후 1초 대기하도록 구성했습니다.

| 가상 사용자 | 요청 수 | 평균 응답 | P95 | HTTP 실패율 |
|---|---:|---:|---:|---:|
| 5 | 100 | 13.43ms | 15.08ms | 0% |
| 10 | 300 | 8.23ms | 10.12ms | 0% |
| 30 | 900 | 7.48ms | 11.94ms | 0% |
| 50 | 1,500 | 6.46ms | 12.44ms | 0% |

### 분석

- 가상 사용자 50명까지 모든 HTTP 요청이 성공했습니다.
- 50명 조건의 P95 응답 시간은 12.44ms였습니다.
- 요청 사이에 1초 대기하므로 최대 처리량 측정 결과는 아닙니다.
- 상품 데이터가 적은 환경에서 측정된 결과이므로 대용량 데이터 환경의 성능을 대표하지 않습니다.

## 3. Redis 캐시 ON/OFF 비교

대상 API: `GET /api/products/1`

조건: VU 10, 30초, 회차별 300건 요청.

상품 기본 정보에 Redis 캐시를 적용하며, 재고 수량은 PostgreSQL에서 조회합니다.

| 조건 | 평균 응답 | P95 | HTTP 실패 |
|---|---:|---:|---:|
| ON 1차 | 12.21ms | 15.97ms | 0건 |
| ON 2차 | 10.39ms | 11.91ms | 0건 |
| OFF 1차 | 18.31ms | 20.87ms | 0건 |
| OFF 2차 | 21.04ms | 14.33ms | 20건 |
| OFF 3차 | 9.22ms | 13.23ms | 0건 |

### 분석

- 일부 측정에서는 Redis 캐시 사용 시 평균 및 P95 응답 시간이 낮았습니다.
- 캐시 OFF 반복 측정에서 HTTP 요청 20건이 실패했으나, 재측정에서는 재현되지 않았습니다.
- 해당 오류의 정확한 원인은 확인되지 않았습니다.
- 캐시 OFF 3차 측정은 캐시 ON보다 평균 응답 시간이 낮았습니다.
- 따라서 현재 데이터만으로 Redis 캐싱의 일관된 성능 개선율을 확정할 수 없습니다.

## 4. 동시 주문 및 재고 정합성 테스트

대상 API: `POST /api/orders`

서로 다른 멱등성 키를 사용하여 동시 주문을 요청했습니다.

초기 재고는 10개이며 각 주문의 수량은 1개입니다.

| 항목 | 20건 요청 | 100건 요청 |
|---|---:|---:|
| 초기 재고 | 10개 | 10개 |
| HTTP 201 | 10건 | 10건 |
| HTTP 409 | 10건 | 90건 |
| 예상 외 응답 | 0건 | 0건 |
| 최종 재고 | 0개 | 0개 |
| 평균 응답 시간 | 258.34ms | 229.64ms |
| P95 응답 시간 | 295.30ms | 311.88ms |
| 최대 응답 시간 | 296.07ms | 329.09ms |

### 검증 결과

초기 재고 10개를 대상으로 100건의 동시 주문을 요청한 결과:

- 주문 성공 10건
- 재고 부족 응답 90건
- 최종 재고 0개
- 예상하지 못한 HTTP 응답 0건

**테스트한 두 시나리오 모두 초과 판매 없이 재고 정합성을 유지했습니다.**

### 참고 사항

`per-vu-iterations` 실행 방식으로 요청 시작 시점을 가깝게 맞췄지만, 모든 HTTP 요청이 정확히 같은 순간 서버에 도달하는 것은 아닙니다.

20건과 100건 테스트는 각 1회 수행했으므로 응답 시간 차이를 일반적인 성능 추세로 단정할 수 없습니다.

## 5. 결론

이번 성능 테스트를 통해 다음을 확인했습니다.

1. 상품 목록 조회는 VU 50 조건에서 1,500건 모두 정상 응답했습니다.
2. Redis 캐싱은 일부 조건에서 응답 시간 개선을 보였지만, 결과의 일관성은 추가 검증이 필요합니다.
3. 동시 주문 100건에서도 초기 재고 10개를 정확하게 차감하고 초과 판매를 방지했습니다.

향후에는 데이터 규모 확대, 반복 부하 테스트, DB 커넥션 풀 및 락 대기 시간 분석을 진행할 수 있습니다.
